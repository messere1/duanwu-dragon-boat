# 河湾与无人机跟拍

本次调整保留了两艘龙舟及村镇中心的造型。河道在 X=28 米之后进入第一道弯，至 X=100 米向北偏移 28 米，再转回形成 S 形河湾。村镇中心仍有一段直水，方便展示起划、并行竞渡和终点门架。

河床与水面分开建模：河床包含深槽、浅肩和局部冲刷起伏，水面只保留小幅波动。下游增加不规则碎石岸和散落卵石，村外地面增加缓慢起伏。石岸、道路、农田和地形采用相同的坐标变换；房屋作为完整物体移动、转向，避免将门窗和屋顶拉弯。原有两座下游桥移至 X=122 和 X=164，避开计划航程内的人物与旗杆。

## 后续 26 秒动画方案

龙舟沿两段三次 Bézier 中心线前进，两队沿法向分别偏移 1.8 米。相机使用另一组空间 Bézier 控制点，按自己的弧长表移动，视点从侧后方逐步向前追赶，最后升高拉远；高度约 17～30 米。相机不作为龙舟子节点，也不采用固定偏移位置。

相机朝向由“相机位置、龙舟稍靠前的目标点、固定世界上方向”计算 lookAt 矩阵；不直接把曲线切线当作视线。最终程序中还可对目标采用 `1-exp(-lambda*dt)` 的帧率无关平滑，避免桨手摆动或船体摇摆传到镜头。

`models/animation_route_plan.json` 保存独立控制点、26 秒时间轴以及弧长采样结果；`previews/24_drone_route_plan.svg` 是同一时刻的船位和机位连线示意。它们用于后续实现和讨论，当前并非已经完成的动画视频。Blender 源文件和 OBJ、GLB 目前仍为静态建模成果。

## 环境导入约定

调整后的完整环境以 `scene_preview.obj` 或 `dragonboat_scene.glb` 的实际网格为准。各建筑单体 OBJ 继续保留局部坐标和原始造型，作为可复用部件；`scene_layout.json` 中 `scene_mesh_deformed` 为 true 的道路、地形、石岸不能只把旧单体按矩阵摆回去。后续 OpenGL 应加载完整环境的分组网格，并将两艘龙舟单独作为动态实例。

本次处理脚本为 `tools/refine_river_environment.py`，首次执行会将修改前的 Blender 文件备份到工程外 `_work/dragonboat/before_river_refinement`，重复执行均从该备份开始，避免多次叠加弯曲。`river_routes.py` 保存河线和两条运动路线的数学定义。

河谷末端补有低山鞍部，避免沿水面远望时看到地形边界。下游岸边由起伏地表与实体侵蚀断面连接，水面保持较稳定的水位。`bank_replacement_groups.obj` 是局部网格替换的检查文件，完整场景已经包含这些内容，使用时无需再叠加加载。

在另一台电脑上使用交付文件时，可直接编辑已有 Blender 源文件。若需要从脚本重建，先生成材质并运行 `build_models.py` 得到未弯曲的基础场景，再运行 `refine_river_environment.py`；修改前备份不包含在建模压缩包内，脚本会阻止对已有弯曲场景再次叠加处理。
